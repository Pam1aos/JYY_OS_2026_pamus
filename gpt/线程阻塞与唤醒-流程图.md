# 线程阻塞与唤醒：可视化流程图

> 目标：4 个 worker 只在启动时创建一次。
> 之后每次矩阵乘法，只是「换参数 → 唤醒 → 计算 → 再次睡眠」。
> 本文只画流程和状态，不写具体实现代码。

---

## 1. 角色

```text
┌─────────────────────────────────────────────────────────────┐
│                            main                             │
│  · 唯一发布任务的人                                          │
│  · 写共享参数槽                                              │
│  · 在两道门上等待 / 放行                                     │
└─────────────────────────────────────────────────────────────┘
              │ 写参数、开门
              ▼
┌─────────────────────────────────────────────────────────────┐
│                    worker 1 / 2 / 3 / 4                     │
│  · 创建后一直活着                                            │
│  · 平时睡在第一道门上                                        │
│  · 醒来后读参数，算自己的那一段                              │
│  · 算完睡在第二道门上，等 main                               │
└─────────────────────────────────────────────────────────────┘

共享资源：
┌───────────────────────────────────────┐
│  参数槽：out / inp / weight / bias     │
│          B / T / C / OC               │
└───────────────────────────────────────┘
     ▲ 写：main（开门之前）
     │ 读：worker（开门之后）
```

## 2. 线程生命周期总览（状态机）

```text
                    pthread_create
                          │
                          ▼
                 ┌─────────────────┐
                 │ WAITING_GATE_1  │◄───────────────────────┐
                 │  （睡眠，等任务）│                        │
                 └────────┬────────┘                        │
                          │                                 │
                          │ 门 1 打开（全员到齐）             │
                          ▼                                 │
                 ┌─────────────────┐                        │
                 │   COMPUTING     │                        │
                 │ 读参数、算自己的 │                        │
                 │ o 区间          │                        │
                 └────────┬────────┘                        │
                          │                                 │
                          │ 计算完成                         │
                          ▼                                 │
                 ┌─────────────────┐                        │
                 │ WAITING_GATE_2  │                        │
                 │  （睡眠，等 main）│                        │
                 └────────┬────────┘                        │
                          │                                 │
                          │ 门 2 打开                        │
                          └─────────────────────────────────┘
                          │
                          │ 若收到退出标志
                          ▼
                       EXIT
```

要点：

- 线程**只有在创建时**走一次 `pthread_create`；
- 之后一直在 `WAITING_GATE_1 → COMPUTING → WAITING_GATE_2` 之间循环；
- `WAITING_*` 是真正的睡眠，不占 CPU。

## 3. 一次 matmul 的完整时序

```text
时间 ───────────────────────────────────────────────────────────────►

main:
   [写参数槽]──►[到 Gate1]────────[等待]────────►[到 Gate2]──►[返回]

worker1:
   [睡在 Gate1]──►[醒]──►[计算 o 段 1]──►[到 Gate2]──►[睡回 Gate1]
worker2:
   [睡在 Gate1]──►[醒]──►[计算 o 段 2]──►[到 Gate2]──►[睡回 Gate1]
worker3:
   [睡在 Gate1]──►[醒]──►[计算 o 段 3]──►[到 Gate2]──►[睡回 Gate1]
worker4:
   [睡在 Gate1]──►[醒]──►[计算 o 段 4]──►[到 Gate2]──►[睡回 Gate1]
```

### 关键顺序

```text
1. main 先把参数写好
2. main 到达 Gate1
3. Gate1 到齐 → 4 个 worker 同时被放行
4. worker 读参数、计算
5. worker 到达 Gate2
6. main 到达 Gate2
7. Gate2 到齐 → worker 回到 Gate1 睡眠，main 返回
```

### 为什么需要两道门

```text
Gate 1：保证 worker 不会在参数写好之前开始计算
Gate 2：保证 main 不会在 worker 算完之前进入下一个算子
```

少任何一道都会出错，见第 9 节。

## 4. 「门」的内部计数可视化

以一次 matmul 为例，参与者 = 4 个 worker + 1 个 main = 5 人。

```text
初始：
  Gate1 到达数：0 / 5

worker 先到：
  worker1 到达 → 1 / 5   （睡）
  worker2 到达 → 2 / 5   （睡）
  worker3 到达 → 3 / 5   （睡）
  worker4 到达 → 4 / 5   （睡）

main 最后到达：
  main    到达 → 5 / 5
             │
             ▼
        计数清零，轮次 +1
        广播：所有睡眠者被唤醒
             │
             ▼
        5 个人一起继续
```

### 第二道门同理

```text
worker 算完后：
  worker1..4 到达 → 1/5, 2/5, 3/5, 4/5   （睡）
  main 到达       → 5/5
                   │
                   ▼
              全部放行
              worker 回到 Gate1 继续睡
              main 从 matmul 返回
```

### 门是「可复用」的

```text
第 1 次 matmul：Gate1 开 → 计算 → Gate2 开
第 2 次 matmul：同一个 Gate1 再开 → 计算 → 同一个 Gate2 再开
...
```

门只是把「一轮」和「下一轮」分开，不区分是哪一次 matmul。

## 5. 参数是怎么「重新传」的

```text
      main                                worker
       │                                    │
       │  ① 写共享参数槽                     │  （还在 Gate1 睡）
       │     out/inp/weight/bias/B/T/C/OC   │
       │                                    │
       │  ② 到达 Gate1                       │
       │────────── 门开 ────────────────────►│
       │                                    │  ③ 读参数槽
       │                                    │  ④ 计算自己的 o 区间
       │                                    │
       │  ⑤ 到达 Gate2                       │
       │◄───────── 门开 ─────────────────────│
       │                                    │
       ▼                                    ▼
    下一个算子                         回到 Gate1 睡
```

要点：

- 参数不是通过 `pthread_create` 传的，而是放在**共享参数槽**里；
- **写参数一定发生在 Gate1 之前**；
- **读参数一定发生在 Gate1 之后**；
- 门的同步机制保证了「写完之后才读」，这不仅是顺序问题，也是内存可见性问题。

## 6. 多轮复用：线程不重建

```text
程序开始
   │
   ├─ 创建 4 个 worker（仅此一次）
   │
   ├─ matmul #1   ：Gate1 → 计算 → Gate2
   ├─ matmul #2   ：Gate1 → 计算 → Gate2
   ├─ matmul #3   ：Gate1 → 计算 → Gate2
   │
   │        ... 重复约 392 次 ...
   │
   ├─ matmul #392 ：Gate1 → 计算 → Gate2
   │
   └─ 通知退出 → join 4 个 worker → 结束
```

线程的时间轴：

```text
worker 生命周期：
  ├────────────────────────────────────────────────────────────┤
  创建                                                        退出
   │                                                            │
   ├─ Gate1 ─ 计算 ─ Gate2 ─ Gate1 ─ 计算 ─ Gate2 ─ ... ─ Gate1 ─┤
```

## 7. 新旧模型对比

### 旧：每次 matmul 创建/销毁

```text
matmul #1：
  main ──► create w1..w4 ──► 计算 ──► join w1..w4

matmul #2：
  main ──► create w1'..w4' ──► 计算 ──► join w1'..w4'

matmul #3：
  main ──► create w1''..w4'' ──► 计算 ──► join w1''..w4''

...
总计：约 392 × 4 = 1500+ 次线程创建
```

### 新：常驻 worker

```text
main ──► create w1..w4 ──────────────────────────────────► join w1..w4
             │
             ├─ Gate1 ─ 计算 ─ Gate2
             ├─ Gate1 ─ 计算 ─ Gate2
             ├─ ...
             └─ Gate1 ─ 计算 ─ Gate2

总计：4 次线程创建
```

## 8. 操作系统层面的「阻塞」和「唤醒」

```text
worker 调用等待原语
        │
        ▼
┌───────────────────────────────┐
│ 进入内核：加入等待队列         │
│ 线程状态：SLEEPING             │
│ CPU 占用：0                    │
└───────────────────────────────┘
        │
        │ main 触发唤醒（广播/释放）
        ▼
┌───────────────────────────────┐
│ 内核把线程标记为 RUNNABLE      │
│ 调度器选一个 CPU 让它继续      │
└───────────────────────────────┘
        │
        ▼
worker 从「等待原语」之后继续执行
```

对比：

```text
睡眠等待（条件变量/信号量/门）：
   worker ──► 内核等待队列 ──► 被唤醒 ──► 继续
   CPU：0

忙等（自旋）：
   worker ──► while (没任务) { } ──► 继续
   CPU：100%（浪费）
```

## 9. 两道门的比喻

### 门 1：起跑门

```text
worker 都已就位，但参数还没写好
   │
   │  main：参数写好了，开门
   ▼
所有 worker 同时起跑
```

没有门 1 的后果：

```text
main:    [还在写参数] ──────────────►
worker:  [已经开始读参数] ──► 读到旧值/半成品 ──► 结果错误
```

### 门 2：终点门

```text
worker 都跑完了，但 main 还没确认
   │
   │  main：我也到了，开门
   ▼
worker 回去休息，main 进入下一阶段
```

没有门 2 的后果：

```text
worker:  [还在写 out] ──────────────►
main:    [已经开始下一个算子，读 out] ──► 读到半成品 ──► 结果错误
```

## 10. 错误流程可视化

### 错误 A：只有起跑门，没有终点门

```text
main:    Gate1 ──► 进入 attention（不等 worker）
worker:  Gate1 ──► 计算 matmul ──► 写 out

             ▲
             └── main 读 out 时，worker 还没写完
```

### 错误 B：参数写在开门之后

```text
main:    Gate1 ──► 写参数
worker:  Gate1 ──► 读参数（可能读到旧值）
```

### 错误 C：worker 忙等

```text
worker:  while (没有任务) { }   ← CPU 100%，4 个核被烧满
```

### 错误 D：过早 join

```text
main:    join worker ──► 等待 worker 退出
worker:  在 Gate1 睡眠，永远等不到退出信号 ──► 死锁
```

正确顺序：

```text
先设置退出标志
再打开 Gate1 让 worker 醒来看到标志
最后 join
```

## 11. 自检清单

```text
[ ] 线程只创建一次吗？
[ ] 参数写在 Gate1 之前吗？
[ ] worker 读参数在 Gate1 之后吗？
[ ] 每次 matmul 都有 Gate2 吗？
[ ] worker 等待时是睡眠，不是自旋吗？
[ ] 退出时先置标志、再唤醒、最后 join 吗？
[ ] perf script 里只有 4~5 个 tid 吗？
```

全部打勾，说明「阻塞—唤醒—重新传参」的模型是正确的。

## 12. 一页总结图

```text
                    ┌──────────────────────────────┐
                    │            main              │
                    │  写参数 → Gate1 → Gate2 → ... │
                    └───────┬──────────────▲───────┘
                            │ 开门          │ 等完成
          ┌─────────────────┼───────────────┼─────────────────┐
          ▼                 ▼               │                 ▼
   ┌────────────┐   ┌────────────┐   ┌────────────┐   ┌────────────┐
   │  worker 1  │   │  worker 2  │   │  worker 3  │   │  worker 4  │
   │ 睡→算→睡   │   │ 睡→算→睡   │   │ 睡→算→睡   │   │ 睡→算→睡   │
   └────────────┘   └────────────┘   └────────────┘   └────────────┘
          │                 │               │                 │
          └─────────────────┴───────┬───────┴─────────────────┘
                                    ▼
                          共享参数槽（每次覆盖）
```

> **线程不重建；参数每次覆盖；两道门保证顺序；等待时真正睡眠。**
