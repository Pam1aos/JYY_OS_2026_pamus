# M5: 并行内存分配器（mymalloc）实验指导

> 来源：<https://jyywiki.cn/OS/2026/labs/M5.md>
> 框架代码：`git pull origin M5` 获取的 `mymalloc/` 目录
> 整理日期：2026-11-11

---

## 1. 实验概览

实现一个 **freestanding 环境下可用的、多处理器安全的内存分配器**：

```c
void *mymalloc(size_t size);   // 分配
void myfree(void *ptr);        // 释放
```

你只能调用框架提供的大块内存接口（它们封装了 `mmap` / `munmap`）：

```c
void *vmalloc(void *addr, size_t length);  // length 必须是 4096 的倍数
void vmfree(void *addr, size_t length);
```

除此之外，不能使用任何其他库函数（freestanding 环境，没有 libc、没有 pthreads）。
Online Judge 评测时会**覆盖你修改过的 `vmalloc` / `vmfree`**。

---

## 2. 为什么“找不到 main 的处理逻辑”

这是最容易困惑的地方：**M5 没有一个需要你实现的交互式 main**。

```
mymalloc/
├── mymalloc.c        ← 你真正要实现的库（mymalloc / myfree）
├── mymalloc.h        ← 接口 + 自旋锁
├── start.c           ← vmalloc/vmfree（mmap 封装）+ freestanding 的 _start/main
├── tests/
│   ├── main.c        ← 测试程序的 main（只是占位）
│   └── tests-trivial.c ← 真正的测试用例（SystemTest）
└── Makefile
```

### main 在哪里

`tests/main.c`：

```c
#include <stdio.h>

int main() {
    printf("mymalloc tests\n");
}
```

它只打印一行。TestKit 的 `SystemTest` 会先在子进程中调用这个 `main()`，**然后**才执行测试体：

```c
SystemTest(trivial, ((const char *[]){})) {
    int *p1 = mymalloc(4);      // ← 测试真正调用的地方
    ...
}
```

所以：

- **没有命令行参数、没有 stdin/stdout 协议**；
- 测试**直接调用** `mymalloc` / `myfree`；
- 你只需要实现 `mymalloc.c` 里的库函数；
- `main` 的存在只是为了把程序链接成可执行文件。

一句话：**这是一个库实验，不是一个命令行程序实验。**

## 3. 功能要求（必须满足）

### 3.1 正确性

| 要求 | 说明 |
|---|---|
| 原子性 | 多线程同时 `malloc/free` 时结果正确；一个 CPU 上分配的内存可能在另一个 CPU 上释放 |
| 无重叠 | 每次分配返回独立区域，生命周期内不与任何其他块共享地址 |
| 8 字节对齐 | 返回地址低 3 位必须为 0 |
| 无内存泄漏 | `myfree` 释放的内存必须能被后续 `mymalloc` 重新利用 |
| 错误处理 | 无法满足请求时返回 `NULL` |
| 不初始化内存 | 允许不清零；清零也可以 |

### 3.2 内存与静态数据限制

- **所有静态内存（代码 + data + bss）不能超过 1 MiB**；
- 管理堆区的数据结构必须**放在堆里**（通过 `vmalloc` 获得），不能开巨大的静态数组；
- 实际使用的内存不能超过申请内存的 **4 倍**（初始阶段的合理开销不计入）。

### 3.3 并发限制

- 只能使用框架提供**自旋锁**实现互斥；
- 提交的代码**不能调用 pthreads**；
- 允许“一把大锁保平安”作为正确性基线，但性能测试（hard tests）可能要求并行度。

### 3.4 freestanding

提交代码不能调用任何 libc 函数：

- ❌ `printf`、`memset`、`memcpy`、`malloc`、`pthread_create`；
- ✅ 你只能使用 `vmalloc` / `vmfree`、自旋锁、自己实现的辅助函数。

调试代码要用 `#ifndef FREESTANDING` 隔离，否则会被 freestanding 检查拒绝。

## 4. 框架代码详解

### 4.1 `mymalloc.h`

提供自旋锁：

```c
typedef struct {
    atomic_int status;
} spinlock_t;

#define LOCKED   1
#define UNLOCKED 0

static inline void spin_lock(spinlock_t *lock) {
    int expected;
    do {
        expected = UNLOCKED;
    } while (!atomic_compare_exchange_strong(&lock->status, &expected, LOCKED));
}

static inline void spin_unlock(spinlock_t *lock) {
    atomic_store_explicit(&lock->status, UNLOCKED, memory_order_release);
}
```

以及四个函数声明：`mymalloc` / `myfree` / `vmalloc` / `vmfree`。

### 4.2 `mymalloc.c`

骨架：

```c
spinlock_t big_lock;
long malloc_count;   // 可删除

void *mymalloc(size_t size) {
    spin_lock(&big_lock);
    malloc_count++;
    spin_unlock(&big_lock);
    return NULL;     // ← 要改成真正的分配逻辑
}

void myfree(void *ptr) {
    // ← 要改成真正的释放逻辑
}
```

### 4.3 `start.c`

两种环境：

- **非 FREESTANDING**（有 libc）：

  ```c
  void *vmalloc(void *addr, size_t length) {
      return mmap(addr, length, PROT_READ|PROT_WRITE,
                  MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
  }
  void vmfree(void *addr, size_t length) { munmap(addr, length); }
  ```

- **FREESTANDING**（`-DFREESTANDING`）：只提供空的 `_start` 和 `main`。
  如果本地 `make check` 需要链接通过，你需要在 `#ifdef FREESTANDING` 下自己实现 `vmalloc` / `vmfree`，例如“一块静态数组 + 简单 bump 分配器”。

> 注意：评测时它自己的 `vmalloc` / `vmfree` 会覆盖你的实现，所以静态临时内存不会带到正式评测里；但本地 check 需要它们。

### 4.4 `Makefile`

```make
NAME := $(shell basename $(PWD))
export MODULE := M5

SRCS   := $(shell find tests/ -maxdepth 1 -name "*.c")
CFLAGS := -I.

all: $(NAME) check

check:
	gcc -DFREESTANDING -I. \
	    -ffreestanding -static -nostdlib -nostartfiles -no-pie \
	    -o malloc-check *.c && \
	        rm -f malloc-check

include ../oslab.mk
include ../.shadow/oslab.mk
```

- `all` 会同时构建测试程序并执行 freestanding 检查；
- `SRCS` 只收集 `tests/*.c`，用于测试可执行文件；
- `check` 用 `*.c`（即 `mymalloc.c` + `start.c`）在 freestanding 模式下编译，验证你没有偷偷调用 libc。

## 5. 推荐实现路线

### 5.1 基本数据结构

在堆区里维护空闲链表，每个块带头部：

```c
typedef struct block {
    size_t size;          // 块总大小（含头部），8 字节对齐
    int    free;          // 是否空闲
    struct block *next;   // 下一个空闲块
    struct block *prev;   // 上一个空闲块（可选）
} block_t;
```

- 头部大小需要对齐到 8 字节；
- 返回给用户的地址 = 头部之后（`(char *)b + sizeof(block_t)`），必须 8 字节对齐；
- `free_list` 是指向堆中空闲块的指针（这是一个很小的静态变量，符合 1 MiB 限制）。

### 5.2 初始化与堆扩展

第一次分配时：

```text
free_list == NULL
  → vmalloc(NULL, 4096 * k)   // k 根据请求大小决定
  → 把这块内存初始化成一个大的空闲块
  → 挂入 free_list
```

后续如果找不到足够大的空闲块，可以继续 `vmalloc` 扩展堆，或者返回 `NULL`。

### 5.3 mymalloc

```text
1. 请求大小 size → 向上对齐到 8 的倍数，并加上头部大小
2. 加锁
3. 遍历空闲链表，找第一个 size >= 请求的块（first-fit）
4. 找到：
     - 如果剩余空间足够组成一个新块，就切分
     - 从空闲链表摘除
     - 标记为已分配
     - 返回 payload 地址
5. 找不到：
     - vmalloc 新页（4096 的倍数），加入空闲链表后重试
     - 仍失败 → 返回 NULL
6. 解锁
```

### 5.4 myfree

```text
1. 由 payload 地址反推出块头
2. 加锁
3. 标记为空闲，插入空闲链表
4. 与相邻的空闲块合并（减少碎片）
5. 解锁
```

合并需要找到**物理上相邻**的块，两种常见做法：

- 每个块保存 `size`，并维护按地址排序的空闲链表，前后查找邻居；
- 给每个块加一个 footer（记录块大小），通过 `payload - footer` 找到前一个块。

### 5.5 对齐

- `sizeof(block_t)` 必须是 8 的倍数；
- 请求大小向上对齐到 8；
- 返回地址 = `(char *)block + sizeof(block_t)`，满足低 3 位为 0。

### 5.6 malloc(0)

`malloc(0)` 的行为是 implementation-defined：

- 返回 `NULL`；
- 或返回一个唯一的最小块（例如 8 或 16 字节）。

测试里会调用 `mymalloc(0)` 十万次（并发测试），只要不崩溃即可。选一种策略并保持 `myfree` 一致。

### 5.7 并发控制

最直接的基线：

```c
spin_lock(&big_lock);
... 修改空闲链表 ...
spin_unlock(&big_lock);
```

这满足“原子性”，但全局锁会成为性能瓶颈（hard tests 可能因此失败）。

### 5.8 freestanding

- 所有调试输出用 `#ifndef FREESTANDING` 包起来；
- 不要调用 `memset` / `memcpy`，需要时自己写循环；
- `check` 编译失败时，第一个错误通常就是“用了 libc 函数”。

## 6. 性能优化（Hard Tests）

课程明确提示：性能瓶颈主要在**多线程争抢同一把锁**。现代分配器的思路是**区分 fast path / slow path**，让常见分配在线程本地完成。

### 6.1 线程本地缓存 / 每线程 arena

思路：

1. 用 `gettid()` 识别当前线程；
2. 每个线程维护自己的空闲链表（arena / cache）；
3. 线程本地没有内存时，才去全局堆加锁申请一批；
4. 释放时优先放回线程本地链表；
5. 线程退出时把本地内存还回全局堆（可选）。

freestanding 环境下获取线程 ID：

```c
static inline pid_t gettid(void) {
    pid_t tid;
    __asm__ volatile (
        "syscall"
        : "=a" (tid)
        : "0" (SYS_gettid)
        : "rcx", "r11", "memory"
    );
    return tid;
}
```

> 这是课程页面给出的写法；`SYS_gettid` 来自 `<sys/syscall.h>`，如果 freestanding 下没有，可以直接用数字或自己定义。

### 6.2 fast / slow path

- **fast path**：线程本地链表非空 → 直接切分，不加全局锁；
- **slow path**：本地为空 → 加全局锁，从全局堆取一批块或 `vmalloc` 新页。

### 6.3 减少碎片

- 合理的块大小分级（size class）；
- 相邻空闲块合并；
- 大块释放时考虑 `vmfree` 归还给系统。

### 6.4 关于“不要用区间树”

课程建议不要一开始就上复杂树结构；现代分配器更多靠“系统”方法（per-thread arena）而不是精巧算法。先把正确性做好，再用真实 workload 驱动优化。

## 7. 测试方法

### 7.1 构建与运行

```bash
cd os2026/mymalloc
make clean && make        # 构建 + freestanding 检查
TK_RUN=1 ./mymalloc       # 跑 TestKit
TK_VERBOSE=1 ./mymalloc   # 失败时看捕获输出
```

> M5 的 `main` 不读 stdin，因此不需要 `< /dev/null`。

### 7.2 已有测试

| 测试 | 检查内容 |
|---|---|
| `trivial` | 两次 `mymalloc(4)` 非空、地址不同、可写、值正确，`myfree` 不崩 |
| `vmalloc` | `vmalloc` 返回非空、4096 对齐、不同地址，`vmfree` 正常 |
| `concurrent` | 4 个线程各分配 100000 次，检查 `malloc_count == 4N`（可删除这个测试和 `malloc_count`） |

### 7.3 建议自己补充的测试

课程的提示：**几个简单的 unit test 远远不够**，真正的难点是并发 bug 和性能。

建议：

1. **顺序压力测试**：随机生成 malloc/free 序列，记录每次地址和大小，结束后检查：
   - 是否有重叠（区间相交）；
   - 是否 double free / use-after-free；
   - 分配是否全部成功（在内存充足时）；
2. **并发压力测试**：多个线程同时 malloc/free，每个线程只操作自己分配的块；
3. **跨线程释放**：一个线程分配、另一个线程释放（实验要求支持）；
4. **边界测试**：`malloc(0)`、连续多次失败、释放后再分配、超大请求；
5. **长时间运行**：修改 `../testkit/testkit.h` 里的 `TK_TIME_LIMIT_SEC`（默认 5 秒），让压力测试跑足够久。

### 7.4 日志与离线校验

在测试里打印：

```
[ALLOC] ptr=0x... size=123
[FREE ] ptr=0x...
```

然后用脚本离线检查：

- 同一地址是否在 free 之前被再次分配；
- free 的地址是否是某次分配返回的地址；
- 分配的区间是否互相重叠。

注意：日志本身会造成 “probe effect”，可能掩盖并发问题，建议同时保留无日志的压力测试。

## 8. 常见坑

| 坑 | 说明 |
|---|---|
| 以为要实现 main | **不需要**；测试直接调用 `mymalloc`，`tests/main.c` 只是占位 |
| `make` 报 `undefined reference to 'main'` 或只编译了 `mymalloc.c`/`start.c` | `.shadow/oslab.mk` 里的 `SRCS :=` 覆盖了本目录 Makefile 的 `SRCS`。可在 include 之后重新赋值，或用 `override SRCS := $(shell find tests/ -maxdepth 1 -name "*.c")` |
| freestanding 检查失败 | `mymalloc.c` 里用了 `printf`/`memset`/`pthread` 等 libc 函数 |
| `vmalloc` 长度不是 4096 的倍数 | 会失败；扩展堆时向上取整到页大小 |
| 静态数组过大 | 总静态内存不能超过 1 MiB；元数据要放在堆里 |
| 没有 8 字节对齐 | 返回地址低 3 位必须为 0 |
| double free / 非法 free | 属于 undefined behavior，测试不会故意覆盖；但自己写测试时不要依赖 |
| 内存占用超过 4 倍 | 碎片控制要好，否则 Judge 判错 |
| 只用一把大锁 | 正确性可以，但 hard test 的性能可能不够 |
| 多线程下没有保护 `free_list` | 数据竞争；所有共享结构都在锁内访问 |
| `malloc(0)` 崩溃 | 选一个明确策略（NULL 或最小块） |

## 10. 一句话总结

M5 不是命令行实验，而是一个**库实现**实验：

> 用 `vmalloc` 拿到 4096 对齐的大块内存，自己维护空闲链表（块头 + 切分 + 合并），用自旋锁保证并发正确性；先做到“一把大锁保平安”，再通过**线程本地 arena / fast-slow path** 提升并行性能。

`main` 不用你管——真正要写的是 `mymalloc.c` 里的 `mymalloc` 和 `myfree`。
