# split_block：两种切分方式示意图

> 约定：
> - `BLOCK_SIZE = sizeof(block_t)`（块头大小，含 `size / is_free / next`）
> - `min_block = 8`（最小 payload）
> - `total = align8(size) + BLOCK_SIZE`（本次分配需要的块总大小）
> - 块头里的 `size` 表示**本块总大小（含块头）**
> - 地址从左到右递增

---

## 0. 切分前的公共状态

从一个空闲块 `b` 中切出 `total` 字节，原块大小为 `old = b->size`。

```text
低地址                                                              高地址
+--------+--------+-------------------------------------------------------+
| chunk  | b 头   | b 的空闲区域（old 字节，含头部）                       |
+--------+--------+-------------------------------------------------------+
         ▲
         └── b（free，在 free_list 中）

free_list ──► b ──► 下一个空闲块 ──► ...
```

前提：

```text
b->size >= total
```

是否真正切分，取决于余量：

```text
old - total >= BLOCK_SIZE + min_block
```

- 满足：切分；
- 不满足：整块分配，不产生余量块。

---

## 1. 方式 A：头部切分（分配块在前，余量在后）

### 1.1 布局

```text
切分前：

b:  +----------+--------------------------------------------------+
    |  b 头    |                 old 字节                          |
    +----------+--------------------------------------------------+
    ▲
    └── b（free）

切分后：

    +----------+------------------+----------+---------------------+
    |  b 头    |   allocated      | rest 头  |   free 余量          |
    | size=total|   payload        | size=    |                     |
    +----------+------------------+----------+---------------------+
    ▲                             ▲
    │                             └── rest（free，进入 free_list）
    └── b（used，已分配）
```

### 1.2 指针关系

```c
block_t *rest = (block_t *)((char *)b + total);

rest->size    = b->size - total;
rest->is_free = 1;

b->size    = total;
b->is_free = 0;

/* 返回给用户的地址 */
return (char *)b + BLOCK_SIZE;
```

### 1.3 free list 的变化

切分前：

```text
prev ──► b ──► next
```

切分后：

```text
prev ──► rest ──► next
```

- `b` 变成已分配块，**必须从 free list 中摘除**；
- `rest` 接替 `b` 的位置；
- 如果 `b` 是链表头，则 `free_list = rest`。

等价写法（一次替换）：

```c
rest->next = b->next;
if (prev)
    prev->next = rest;
else
    free_list = rest;
```

### 1.4 特点

| 优点 | 缺点 |
|---|---|
| 分配块地址靠近原块起点，符合常见布局 | 需要找到 `prev`，或单独处理头节点 |
| 余量块在原块尾部，便于向后合并 | 单链表摘除中间节点麻烦 |

---

## 2. 方式 B：尾部切分（余量在前，分配块在后）

### 2.1 布局

```text
切分前：

b:  +----------+--------------------------------------------------+
    |  b 头    |                 old 字节                          |
    +----------+--------------------------------------------------+
    ▲
    └── b（free）

切分后：

    +----------+---------------------+----------+------------------+
    |  b 头    |   free 余量          | res 头   |  allocated       |
    | size=    |                     | size=total|  payload         |
    +----------+---------------------+----------+------------------+
    ▲                                 ▲
    │                                 └── res（used，已分配）
    └── b（仍然 free，仍在 free_list 中）
```

### 2.2 指针关系

```c
size_t rest_size = b->size - total;

block_t *res = (block_t *)((char *)b + rest_size);

res->size    = total;
res->is_free = 0;

b->size = rest_size;   /* b 仍然是空闲块 */

/* 返回给用户的地址 */
return (char *)res + BLOCK_SIZE;
```

### 2.3 free list 的变化

```text
切分前：free_list ──► b ──► next
切分后：free_list ──► b ──► next
```

- **free list 完全不变**；
- 只修改了 `b->size`；
- 分配块 `res` 本来就不在链表里。

### 2.4 特点

| 优点 | 缺点 |
|---|---|
| **不需要摘除/替换链表节点**，实现最简单 | 分配块地址在空闲块尾部 |
| 不需要 `prev` 指针 | 与“从头分配”的直觉不同，调试时要注意地址 |
| 适合单链表、最小版本 | 合并逻辑要考虑“分配块在尾部”的情况 |

---

## 3. 余量不够时：不切分

如果：

```text
old - total < BLOCK_SIZE + min_block
```

则**不要切分**，整块分配：

```text
切分前：
+----------+--------------------------------------+
|  b 头    |           old 字节                    |
+----------+--------------------------------------+

切分后：
+----------+--------------------------------------+
|  b 头    |   整块给用户（size 仍为 old）          |
+----------+--------------------------------------+
```

- 方式 A：`b` 从 free list 摘除，`b->size` 保持 `old`；
- 方式 B：同样摘除 `b`，整块分配。

此时：

```c
b->is_free = 0;
return (char *)b + BLOCK_SIZE;
```

多余空间是**内部碎片**，`myfree` 时整块回收。

## 4. 当前代码的错误示意

当前实现：

```c
cur_blcok->size -= size;
res_block = (block_t *)((char *)cur_blcok + size);
res_block->is_free = 0;
```

假设 `old = 1000`，`total = 120`：

```text
cur->size 变成 880

+----------+--------------------------------------+
|  b 头    |        880（声明为空闲）              |
+----------+--------------------------------------+
           +----------+---------------------------+
           | res 头   | 分配块（从 120 开始）      |
           +----------+---------------------------+
            ▲
            └── 落在 880 的空闲区域内部 → 重叠
```

问题：

1. 分配块与余量块**地址重叠**；
2. `res_block->size` 没有赋值；
3. 既不是方式 A，也不是方式 B；
4. free list 没有更新。

---

## 5. 两种方式对比

| 项目 | 方式 A（头部） | 方式 B（尾部） |
|---|---|---|
| 分配块位置 | 原块起点 | 原块尾部 |
| 余量位置 | 原块尾部 | 原块起点 |
| 是否修改 `b->size` | 是（改为 `total`） | 是（改为 `old - total`） |
| 是否需要摘除 `b` | **是** | **否** |
| 是否需要 `prev` | 需要（或替换头） | 不需要 |
| 返回 payload | `(char *)b + BLOCK_SIZE` | `(char *)res + BLOCK_SIZE` |
| 适合场景 | 常规布局、便于向后合并 | 最小实现、单链表 |

---

## 6. 必须维护的不变量

无论选哪种方式，切分后都要满足：

```text
1. b->size + rest->size == old          （方式 A）
   或 b->size + res->size == old        （方式 B）

2. 所有块在 chunk 内首尾相接，不重叠、无空隙

3. free list 中每个节点都是 free 块

4. 已分配块不在 free list 中

5. 每个 free 块恰好出现在 free list 中一次

6. 所有块大小是 8 的倍数，payload 地址 8 字节对齐
```

---

## 7. 推荐

- **最小版本**：选方式 B，代码最少，不改 free list；
- **需要向后合并/常规布局**：选方式 A，但要正确维护 `prev` 或替换头节点；
- 无论选哪种，**先把“不切分”的情况处理正确**，再处理切分。
